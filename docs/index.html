Webhooks that don’t lose events.

Post an event once. It’s on disk before you get the answer, then signed and delivered, at least once, through crashes, outages and slow receivers.

On disk before the answer

202 only after the flush that covers the event. Survives kill -9 and power cuts.

Signed, and rotatable

Standard Webhooks signatures. Rotate a secret with both signatures valid, so receivers switch without downtime.

Retry, dead-letter, replay

Nine retries over about three days, then a dead letter you can list and replay.

How it works

One process, two logs. The logs are the truth; the database is optional.

Broken on purpose

The service is killed, its database is cut, its receivers lie, and a separate checker looks for lost, repeated or badly signed deliveries.

What you get

Replay

One event to one endpoint, or a whole endpoint’s dead letters in bulk.

Event filters

Endpoints subscribe to invoice.*; the rest is skipped for free.

Per-endpoint pace

A rate and a concurrency for each; a slow one never stalls the rest.

Circuit breaker

An endpoint that has failed for days is paused, its events kept.

Cron

Schedules that fire exactly once, even if the service is killed mid-fire.

Idempotency

The same key returns the same answer, across crashes.

Operable

/readyz, Prometheus /metrics, graceful stop, backup and restore.

Hard to run unsafe

Scoped tokens, and a production profile that refuses to start open. Deliveries go only to public addresses.

Written in lex-sys

A typed systems language whose compiler writes down what a program may do. That report is checked in CI, so a new foreign call is a change somebody has to approve.

Logs, the PostgreSQL client (SCRAM), DNS, HTTP and signatures are lex-sys too. No unsafe.

Quick start

git clone https://github.com/alpibrusl/lexsys-hooks && cd lexsys-hooks
scripts/build.sh                                  # one binary: build/hooks
mkdir data && echo "0 127.0.0.1 9100 whsec_$(head -c24 /dev/urandom | base64)" > data/endpoints.conf
build/hooks --port 8080 --dir data --allow-private-hosts 1 &
curl -d '{"type":"user.created"}' localhost:8080/events   # {"id":1}

Building needs the pinned lex-sys compiler: the README has the extra lines, and a receiver that verifies each signature.

Not for production yet

  • The 24-hour chaos soak and the capacity figures it gives are in progress; the first two runs found two real bugs, both fixed.
  • https uses OpenSSL until lex-sys’s own TLS has been independently reviewed.
  • One process on one core; put a reverse proxy in front for TLS on the service’s own port.
